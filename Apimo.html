About this project

APImo is a REST API we built so that other projects at our school can consume data from the Pasimo database without having to implement their own database connection. We started by building the core library: the Hibernate session factory, entity classes that mirror the Pasimo schema, and a Jackson configuration to serialise those entities to JSON.

The API exposes seven resource groups, educations, education teams, teams, students, teachers, check-ins, calendars and accounts, each accessible through clean REST endpoints. We documented every endpoint in a shared Postman collection so any consumer project could test and integrate the API straight away.

I was responsible for the education, education-team, team and check-in endpoints, as well as the complete API configuration (Hibernate setup, Jackson serialiser, servlet mapping). I also provided debugging support to my teammates, since I had the most prior experience with Java and REST APIs. Throughout the project we followed an Agile SCRUM process: daily stand-ups, sprint planning, retrospectives and a product backlog maintained in Jira.

Key highlights

  • REST endpoints for 7 resource types: educations, teams, students, teachers, check-ins, calendars and accounts
  • Hibernate ORM mapping complex Pasimo database entities with relationships
  • Jackson configured for clean JSON serialisation, handling circular references between entities
  • Shared Postman collection documenting every endpoint for easy integration by consumer projects
  • Maven build system with clean dependency management across the whole team
  • Full SCRUM workflow over multiple sprints with Jira backlog, stand-ups and retrospectives

Features

Everything the API can do

Education Endpoints

Retrieve all educations or a single education by ID. A separate set of endpoints exposes the education-team junction so consumers can find which teams belong to which education.

Team Endpoints

Query all teams stored in Pasimo or fetch a specific team by its ID. Returns team metadata including name, associated education and member count.

Student & Teacher Endpoints

Look up all students or teachers, or filter by ID. Each response includes relevant profile data such as name, email and linked team or subject, making it easy to build user-facing features on top of the API.

Check-in Endpoints

Access attendance records from the Pasimo database. Endpoints allow filtering check-ins by student or by date range, enabling other applications to display or process attendance data without direct database access.

Calendar Endpoints

Retrieve calendar events and schedules stored in Pasimo. Consumer applications can use these endpoints to show timetable data to students or staff without needing their own scheduling logic.

Account Endpoints

Expose account records from the Pasimo database, allowing other projects to retrieve user credentials and profile information for authentication and personalisation purposes. Also involves authentication logic for accounts.

Tech Stack

The technologies powering APImo

Java

Back-end logic

Core language for all server-side business logic, entity models, request handling and response formatting.

Hibernate

ORM / Persistence

Maps Java entity classes to the existing Pasimo MySQL schema. Handles complex relationships, lazy loading and HQL queries without writing raw SQL.

Jackson

JSON Serialisation

Converts Java objects to JSON responses. Configured with custom serialisers to prevent infinite loops caused by bidirectional entity relationships.

MySQL

Database

The Pasimo relational database containing all school data. APImo connects to it read-only, surfacing its tables through the REST layer.

Postman

API Testing & Docs

Shared collection used to test every endpoint during development and serve as living documentation for teams integrating with the API.

Maven

Build Tool

Manages all project dependencies (Hibernate, Jackson, MySQL connector) and standardises the build process across the whole team.

Challenges & Learnings

Challenges we faced

  • Configuring Hibernate from scratch in a plain Java servlet app, no Spring to auto-wire the session factory, so we had to read the documentation carefully and handle the lifecycle manually.
  • Mapping the pre-existing Pasimo schema to Java entities with bidirectional relationships caused infinite JSON loops until we properly configured Jackson with @JsonManagedReference and @JsonBackReference.
  • Designing a consistent REST URL structure across all seven resource groups so the API felt coherent to any team consuming it.
  • Coordinating work across three developers on a shared codebase, merge conflicts and diverging entity models made early communication essential.

What I learned

  • How to build a REST API in pure Java: servlet setup, request routing, reading path parameters, and writing JSON responses without a framework doing it for you.
  • Deep understanding of Hibernate: entity annotations, session management, lazy vs. eager loading, and writing HQL queries to filter data efficiently.
  • Jackson internals: how object graphs are serialised, why circular references break JSON output, and how to resolve them with annotations and custom serialisers.
  • Using Postman not just for testing but as living API documentation, well-named requests and saved examples let teammates and consumer teams understand the API without extra docs.
  • Running a real SCRUM process: splitting the resource list into sprint tasks, estimating story points, and demoing working endpoints to a product owner at the end of each sprint.
