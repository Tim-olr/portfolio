About this project

Sarah en Tim is a private full-stack web application I built as a Valentine's Day gift for my girlfriend. The idea was simple: create a cosy, personal space where the two of us could store and revisit our shared memories, complete with photos, dates, and captions.

The site features a daily memory highlight on the home screen, a gallery view where all memories are shown as photo cards, and a timeline view where memories appear in chronological order with a scrapbook feel. Both of us can publish new memories, edit or delete existing ones, and leave comments on each other's posts.

Access is invite-only, there is no public registration. I built a small admin panel to manage users and memories. The project taught me Spring Boot from scratch, including REST controllers, Spring Security, JPA with Hibernate, and deploying a Java application to a live server.

Key highlights

Features

Everything the site can do

Daily Memory

Every day the home screen shows a random memory from our collection, so there is always something to smile about when you first open the site.

Gallery View

Browse all memories in a photo-grid layout. Each card shows the photo, the date, and a short caption. Clean and easy to scroll through.

Timeline View

See memories laid out chronologically in a scrapbook-style timeline. Photos appear staggered left and right, giving it a personal, handcrafted feel.

Add / Edit / Delete Memories

Both users can add new memories with a photo, date, and caption. Existing memories can be updated or removed at any time.

Description

We can leave a description to share the story of what we did that day, how we felt, or any funny anecdotes related to the memory. It adds a personal touch and makes each memory more meaningful.

Admin Panel

A dedicated admin view lets me manage user accounts and oversee all memories on the site. Users cannot register themselves — access is granted manually.

Tech Stack

Tools and technologies behind Sarah en Tim

Spring Boot

Backend Framework

Handles the entire server side: routing, REST controllers, authentication with Spring Security, and session management. My first real Spring Boot project.

Hibernate / JPA

ORM / Database

Maps Java entities (Memory, User, Comment) to database tables. JPA repositories handle all CRUD operations cleanly without writing raw SQL.

Maven

Build Tool

Manages all project dependencies and the build lifecycle. Used to package the application as a JAR for deployment.

Spring Security

Authentication

Protects all routes behind login. Only authenticated users can view memories. Admin-only routes are locked behind a role check.

HTML / CSS / JS

Frontend

The frontend is server-rendered with Thymeleaf templates styled to give a warm, cream-yellow scrapbook feel that matches the sentimental nature of the project.

Git / GitHub

Version Control

Full version history throughout development. Separate branches for new features like the memory system and the admin panel.

Challenges & Learnings

Challenges I faced

  • Learning Spring Boot from scratch with no prior experience — figuring out the project structure, annotations, and how all the pieces fit together.
  • Configuring Spring Security correctly so only logged-in users can see the site, while keeping the login page publicly accessible.
  • Handling file uploads and storing images so they persist correctly after the server restarts.
  • Deploying a Spring Boot JAR to a live server and keeping it running reliably.

What I learned

  • Spring Boot fundamentals: controllers, services, repositories, and how the layers communicate through dependency injection.
  • JPA and Hibernate: mapping entities, defining relationships (one-to-many for comments), and letting the ORM manage the database schema.
  • Role-based access control: separating regular user permissions from admin permissions without duplicating logic.
  • That building something with a real emotional purpose makes the hard parts of learning a new framework worth it.
